# 工业制造数据预处理与物理提纯作业规范 (SOP)
## ——以轮胎制造工时偏差分析项目为例

---

## 1. 规范概述与核心原则

在离散制造与工业大数据分析中，数据预处理的质量直接决定了后续模型与统计归因的上限。现场原始数据通常夹杂大量数据库冗余、系统打卡误差、手工录入笔误以及特定的工业物理设计。

为确保数据既能被机器学习算法稳定处理，又不失真地保留车间真实工艺规律，本规范总结了以下**三条不可逾越的预处理高压线**：
1. **时间轴红线（严防时间穿越）**：凡是工单下发排产时（$t_0$）尚未发生的现场执行、结算或质检数据，严禁作为预测输入进入特征库；
2. **算术泄露红线（严防自圆其说）**：目标变量若是通过特定算术公式派生生成的，其所有公式组成项必须从输入端物理隔离，防止模型退化为简易计算器；
3. **物理机理红线（严防无脑插补）**：严格区分“物理上本来就没有”与“采集系统数据丢失”，严禁在全表盲目执行均值或中位数填充。

---

## 2. 原始数据五步清洗与物理提纯规范

```text
原始 MES / ERP 制造导出数据 (例如 53,313 行 × 94 列)
       │
       ▼
【步骤 1：确定性垃圾清理与准常量列剔除】
       │  - 移除导出系统行号、全空格死列、绝对常数列
       │  - 剔除严格代数派生列与文本镜像列
       │  - 过滤单一取值 ≥ 98% 的伪常数列（设立关键工艺保护白名单）
       ▼
【步骤 2：非数值字段四批精准物理提纯】
       │  - 批次 A：二元开关映射 (0/1)
       │  - 批次 B：内嵌真数值正则提取 (去字母前缀、脏空格纠正、乘法解析、规格解耦)
       │  - 批次 C/D：无序类别原汁原味保留干净文本，严禁乱编 1,2,3
       ▼
【步骤 3：物理结构性缺失与采集丢失严格分流】
       │  - 区分“单层胎本来就没有第二层”与“传感器丢数据”
       │  - 结构性缺失：数值型赋 0.0，类别型赋 Not_Present，派生 Has_* 开关列
       ▼
【步骤 4：系统底层微观异常修正与血缘留痕】
       │  - 针对系统跨零点同步产生的微小负数工时/覆盖率，执行安全截断 .clip(lower=0)
       │  - 记录异常行 SHA-256 哈希，标记 NEGATIVE_CLIPPED，做到可溯源
       ▼
【步骤 5：全局去重、0 NaN/0 Inf 绝对断言与机器契约固化】
       │  - 精准去重 (例如 53,313 -> 53,145 行)
       │  - 强行执行 0 空值与 0 极端值断言自检
       │  - 输出标准化机器契约 feature_schema.json
       ▼
进入下一步：统计初筛与工单级建模
```

---

### 步骤 1：确定性垃圾清理与准常量列剔除

#### 1. 现场问题
原始导出的 94 列中充斥着大量历史遗留与系统级垃圾：
- **无意义系统行号**：`Unnamed: 0` 属于导出脚本遗留的行索引；
- **全空格死列**：`PhaseInOut` 字段在全表中整整 **92% 为纯空格字符串**；
- **绝对常数列**：`variant`、`spec_type`、`base_variant`、`base_spec_type` 全表 5.3 万行取值完全固定，无任何方差；
- **严格数学派生列**：
  - `quantity gap` 严格等于实际产量与计划产量的代数差（`QuantityDone - PlannedQuantity`）；
  - `bead_-_bead_circumference`（周长）严格等于 $\pi \times \text{bead\_inner\_diameter}$（内径）；
  - `1_belt_-_width` 严格等于 `2_belt_-_width + 10`；
- **文本镜像双胞胎**：`base_article_development_cluster_name` 与 `article_development_cluster_name` 文本完全一致。

#### 2. 处理规范
1. **显式列表定点剔除**：将上述死列、派生列与镜像列加入确定性删除列表，物理移除；
2. **准常数列阈值过滤**：遍历其余列，凡单一水平取值占比超过 **98%** 的非信息量列统一剔除；
3. **核心工艺字段白名单保护（防呆）**：
   - 过滤准常数列时必须设置保护名单（例如 `1_belt_ply_assembly_-_1_strip_rubber_-_width`）。即使该字段绝大部分规格取值集中，但只要属于核心工艺图纸参数，代码必须显式豁免，并在脚本末尾添加断言核查，严防误删。

---

### 步骤 2：非数值字段的四批物理提纯

#### 1. 现场问题
原始数据中的 34 个非数值列存在严重混乱：
- 部分离散代号（如 `RecipeID`、`OperatorUserID`）被错误识别为大整数（int64），易诱导线性模型产生虚假的连续数值假设；
- 字符串格式存在手滑笔误（例如 `"1400 dtex x2"` 与 `"1400 dtex x 2"` 混用）；
- 文本中隐蔽包含关键物理量（如 `"A=12.5"`、`"6x6"`、`"235/50 R 19"`）。

#### 2. 处理规范
严禁将无序代号简单编为 1, 2, 3 或频次占比，必须按物理属性分为四批精细化处理：

1. **类型归正**：把伪装成数字的代号（`RecipeID`, `OperatorUserID`, `DestinationInfo`）强制转为纯文本字符串；
2. **批次 A（二元物理开关，严格映射为 0.0 / 1.0）**：
   - 原厂配套标识：`oeindicator`（`"N"` $\to 0.0$, `"Y"` $\to 1.0$）；
   - 轮辋垫胶配方：`1_flange_cushion_-_compound`（双配方二元编码为 $0.0 / 1.0$）；
3. **批次 B（内嵌连续物理真值 / 有序工艺提取）**：
   - **前缀剥离**：胎侧参数 `1_sidewall_-_bom_component_setting` 去掉 `"A="` 前缀，直接转为连续浮点数；
   - **字符规范与纤度映射**：帘线结构 `1_wound_cap_ply_-_cf_construction` 先修正空格脏数据，再根据行业标准按总旦数映射为物理数值（如 $1400\text{ dtex} \times 2 = 2800.0\text{ dtex}$）；
   - **正则乘法解析**：钢丝结构 `bead_-_bead_construction`（形如 `"6x6"`），利用正则 `(\d+)x(\d+)` 自动计算乘积，还原钢丝总根数（$36.0$ 根）；
   - **行业标准映射**：速度符号 `speed_symbol`（`H, V, W, Y, (Y)`）映射为对应的设计最高车速（`210, 240, 270, 300, 320 km/h`）；
   - **复合规格正则解耦**：从规格字符串 `tire_size` 中使用正则一分为二，拆解出**断面宽度 `tire_section_width`（mm）**与**扁平比 `tire_aspect_ratio`（%）**两个纯数值列；同时原规格字符串完整保留，供宏观分组使用；
4. **批次 C/D（无序名义类别）**：
   - 对胶料配方、机台代号等名义类别，仅做去除首尾空格处理，**原汁原味保留纯文本字符串**，交由后续支持类别特征的算法（如 CatBoost 原生有序目标编码）处理。

### 步骤 3：物理结构性缺失与随机丢失严格分流

#### 1. 现场问题
数据中大量规格缺失某些构件数据：
- 胎圈加强包布相关字段缺失 **47,787 行**；
- 第二层胎体帘布厚度与宽度缺失 **47,058 行**。
若按传统数据分析思路直接使用全局均值或中位数填充，会凭空捏造出“根本不存在第二层帘布的轻型胎强行加上了厚度”，严重违背工业常识。

#### 2. 处理规范
必须向车间工艺核实构件的物理存在性，确立**结构性缺失（Structural Absence）处理法则**：
1. **数值型物理量赋确定值 0.0**：对于物理上不存在该部件的轮胎，其厚度、宽度强制赋为 `0.0`；
2. **类别型材质赋确定代号**：材质代码统一填入确定字符串 **`Not_Present`**，表明该规格未装配该组件；
3. **显式衍生布尔指示列**：同步生成二元指示开关特征：
   - `Has_2nd_Carcass_Ply = 0 / 1`
   - `Has_Bead_Reinforcement = 0 / 1`
   使算法能够清晰捕捉“单层设计”与“双层设计”之间的结构性跃迁。

---

### 步骤 4：系统底层微观异常修正与血缘留痕

#### 1. 现场问题
现场数据中，`OperatorOverlapSeconds`（打卡秒数）和 `OperatorCoverageRatio`（工时覆盖率）存在 **94 行微小的负数**（如 $-0.01$ 秒）。这是 MES 打卡系统跨零点时间戳时钟同步误差导致的底层噪点。

#### 2. 处理规范
1. **安全截断**：工时与比例在物理现实中严格非负，在清洗阶段使用 `.clip(lower=0)` 将负数安全截断为 `0`；
2. **全流程留痕**：建立行级血缘映射表，将该 94 行打上 `NEGATIVE_CLIPPED` 标志并记录源行哈希；
3. **业务守恒验证**：审计证明，这 94 行记录所属的工单均包含其他正常的正工时打卡记录，截断不会破坏该工单的完工事实，避免整批工单被误删。

---

### 步骤 5：全局去重、0 NaN/0 Inf 绝对断言与契约固化

#### 1. 现场问题
由于车间报表跨班次导出，原始数据包含 168 行完全相同的纯冗余记录。

#### 2. 处理规范
1. **全局去重**：执行全局去重操作，使 53,313 行严格规整为 **53,145 行**；
2. **代码级严格断言（工业交付底线）**：
   清洗流水线执行结束前，必须运行无死角断言校验：
   ```python
   # 必须保证全表 0 空值，杜绝任何静默产生的 NaN
   assert df.isna().sum().sum() == 0, "清洗后数据集仍存在未处理的 NaN 空值！"
   
   # 必须保证全表数值列无正负无穷大极端值
   numeric_cols = df.select_dtypes(include=[np.number])
   assert not np.isinf(numeric_cols).any().any(), "清洗后数值列存在 Inf 极端值！"
   ```
3. **机器契约文件固化**：
   清洗脚本必须同步导出机器可读的 `feature_schema.json`，白纸黑字固化字段属性：
   - 目标标签字段（`target_col`）；
   - 清洗后数据集行列维度；
   - 剔除列明细清单；
   - 49 个数值特征的极值范围；
   - 26 个类别特征的名称与取值频数。

## 3. 工程师落地自检核对表 (Checklist)

在完成任何新车间、新工序的数据预处理后，负责工程师必须逐项签字核对：

| 序号 | 校验维度 | 检查内容与合格标准 | 判定 |
| :---: | :--- | :--- | :---: |
| 1 | **常数与死列** | 全表唯一值列、全空格列（如 `PhaseInOut`）是否已全部剔除？ | `[PASS]` |
| 2 | **代号类型归正** | `RecipeID`、工号等离散代号是否已强转为文本字符串，未被识别为连续整数？ | `[PASS]` |
| 3 | **内嵌真值提取** | 速度代号、胎圈钢丝乘法、复合规格是否已提取出真实物理量纲并与原表一致？ | `[PASS]` |
| 4 | **结构性缺失** | 单层胎体、无加强包布的缺失是否赋为 0 和 `Not_Present`，未执行盲目均值填充？ | `[PASS]` |
| 5 | **负数打卡修正** | 工时与覆盖率中的负值是否已做 `.clip(lower=0)` 并在血缘表中标记 `NEGATIVE_CLIPPED`？ | `[PASS]` |
| 6 | **受保护特征** | 白名单关键出厂工艺特征是否完整保留，未被方差阈值误删？ | `[PASS]` |
| 7 | **数据绝对清洁** | 脚本是否顺利通过 `0 NaN` 与 `0 Inf` 断言，并导出了最新的 `feature_schema.json`？ | `[PASS]` |
